# Vercel runtime for a ChatGPT Apps SDK MCP server

**Research date:** 2026-07-26. **Scope:** current first-party Vercel documentation and official OpenAI Apps SDK/plugin documentation only. The findings are applied by [ADR 0013](../docs/adr/0013-deploy-on-vercel-with-convex.md).

## Recommendation

Use separate long-lived production and staging Vercel projects, each with a strict TypeScript/ESM Node.js Function as the thin `/mcp` Streamable-HTTP transport and the same deployment serving versioned static Evidence-component bundles. Separate projects give Vercel OIDC distinct project subjects without depending on undocumented custom-environment claims. Keep the cohesive stateless Investigation module and all Convex/provider adapters behind it; do not make each MCP tool a separate Function. Choose a Node.js runtime, not Edge: Node has full Node API coverage and supports streaming by default, while Vercel has deprecated Edge Functions in favor of Node Functions. [Vercel runtimes](https://vercel.com/docs/functions/runtimes) [Vercel Function limits](https://vercel.com/docs/functions/limitations) [Vercel OIDC](https://vercel.com/docs/oidc/reference) [Edge deprecation](https://vercel.com/docs/functions/runtimes/edge/edge-functions)

ChatGPT production MCP endpoints must be stable public HTTPS URLs using Streamable HTTP (normally `/mcp`); tools must remain useful without the optional component. The official TypeScript MCP SDK is `@modelcontextprotocol/sdk`; version UI resource identifiers when component HTML/JS/CSS changes. [OpenAI: MCP server](https://developers.openai.com/plugins/concepts/mcp-server) [OpenAI: build MCP server](https://developers.openai.com/plugins/build/mcp-server)

### Proposed topology

```text
ChatGPT ──HTTPS/Streamable HTTP──> Vercel CDN/WAF ──> Node Function: /mcp
                                                     ├─ Investigation module
                                                     ├─ Convex (US East release store/vector index)
                                                     ├─ YouVersion and Gloo providers
                                                     └─ MCP resource -> versioned static Evidence bundle
```

The UI is message-scoped because it is returned as an MCP resource associated with the selected tool, not because Vercel stores message state. Serve immutable, content-hashed JS/CSS under a stable Vercel custom origin; return only rights-permitted per-result hydration in `_meta`, and keep the model-readable `structuredContent` complete without UI. OpenAI requires the server to preserve authorization boundaries and recommends the component origin be allowed by its CSP. [OpenAI: deploy and optional UI](https://developers.openai.com/plugins/build/mcp-server)

## Feasibility and operating constraints

| Concern | Verified platform fact | Architecture consequence |
| --- | --- | --- |
| Streaming | Node Functions support streaming, but no Vercel Function can stream indefinitely because execution is bounded. [Vercel runtimes](https://vercel.com/docs/functions/runtimes) | Stream MCP responses when useful; treat the configured request deadline as an absolute budget and return a valid degraded/abstaining package before it. Test disconnect/cancellation. |
| Duration and body size | Fluid Compute is enabled by default. Its documented maxima are 300s on Hobby and 800s on Pro/Enterprise; a function exceeding its configured duration is terminated. Node request **and response** payloads are limited to 4.5 MB. [Duration](https://vercel.com/docs/functions/configuring-functions/duration) [Limits](https://vercel.com/docs/functions/limitations) | Pro/Enterprise only; explicitly set a route `maxDuration` below the plan maximum and enforce much smaller application limits for question, evidence, replay reference, and result bytes. Do not send files or oversized component hydration through MCP. |
| Fluid Compute / statelessness | Fluid reuses instances and provides optimized concurrency; global state is therefore not a request or user boundary. Node uncaught errors are isolated so in-flight requests can finish before the process stops. Settings in code/`vercel.json` override dashboard defaults. [Fluid Compute](https://vercel.com/docs/fluid-compute) | Reuse only safe clients/caches; retain no conversation, package, auth, or user state in memory. Make every request independently verifiable and use signed bounded references. |
| Region and data | Functions default to `iad1`; Vercel advises running functions in the same/nearest region as the data source. Compute placement is configurable; Pro permits up to three function regions and Enterprise more. [Regions](https://vercel.com/docs/regions) [Fluid Compute](https://vercel.com/docs/fluid-compute) | Initially pin `iad1` with a Convex US East deployment and benchmark provider/ChatGPT latency there. Do not enable multi-region until Convex consistency, provider egress, and signed-reference key behavior are tested. |
| Secrets and environments | Environment values are encrypted at rest, scoped to Production/Preview/Development (and custom environments), affect new deployments only, and are available to both the build and Function runtime. `--sensitive` hides a value after creation but does not make it build-only. [Environment variables](https://vercel.com/docs/environment-variables) [Managing environments](https://vercel.com/docs/environment-variables/manage-across-environments) | Separate production and staging projects and preview credentials. Keep Convex deploy/publisher keys in CI, not Vercel. Previews receive fixtures only—never provider, production Convex, signing, or licensed-corpus secrets. Rotate runtime secrets by redeploying and support signing-key overlap in application code. |
| Custom domain / TLS | Add and DNS-verify a custom domain; Vercel then provisions SSL automatically. Vercel-managed certificates use Let's Encrypt; custom SSL is Enterprise-only. [Custom domain setup](https://vercel.com/docs/domains/set-up-custom-domain) [SSL certificates](https://vercel.com/docs/domains/working-with-ssl) | Use `mcp.<domain>/mcp` as the stable production URL and a separate staging hostname. Gate cutover on DNS, certificate issuance, HTTPS, and MCP initialization—not a changing deployment URL. |
| Logs and privacy | Runtime logs include function output and `console` output in Preview and Production, including request path, user agent, search parameters and outgoing-request metadata; retention varies by plan. Pro/Enterprise Log Drains forward observability to third parties. [Runtime logs](https://vercel.com/docs/logs/runtime) [Drains](https://vercel.com/docs/drains) | Treat platform logging as content-bearing: never log questions, answers, headers/tokens, raw providers, or hydration. Emit only the repository-defined sanitized operational telemetry. Disable broad drains unless its destination, retention, IP handling, sampling, and access controls pass privacy review. |
| Abuse protection | Vercel Firewall provides automatic L3/L4/L7 DDoS mitigation; WAF supports custom/managed rules, IP blocks, challenges, and rate limits. [Firewall](https://vercel.com/docs/vercel-firewall) [DDoS mitigation](https://vercel.com/docs/vercel-firewall/ddos-mitigation) | Add path-specific `/mcp` WAF rate limits and restrictive custom rules before provider calls; enforce a second application/provider budget because anonymous MCP traffic can still be expensive. Exercise block/challenge behavior against ChatGPT connectivity. |
| Deploy and recovery | Preview deployments are isolated URLs; production can promote a tested deployment within its own project. Instant rollback repoints routing without rebuilding, but restores an older build/configuration and turns off automatic production-domain assignment until a later promotion. [Environments](https://vercel.com/docs/deployments/environments) [Promote](https://vercel.com/docs/deployments/promoting-a-deployment) [Rollback](https://vercel.com/docs/deployments/rollback-production-deployment) | Because staging and production are separate projects, deploy production from the exact approved commit and compare source, lockfile, generated-contract, server-build, and component-bundle provenance rather than claiming cross-project artifact promotion. Maintain a tested rollback runbook that also checks Convex schema/release and configuration compatibility; Vercel rollback is not a Convex release rollback. |
| mTLS | The reviewed Vercel custom-domain/TLS documentation covers server certificates and TLS termination, not client-certificate verification or an mTLS configuration surface. [Vercel security](https://vercel.com/docs/security) [SSL certificates](https://vercel.com/docs/domains/working-with-ssl) | Do **not** assume inbound ChatGPT-to-Vercel mTLS is available. The public MCP endpoint must use ordinary HTTPS plus MCP authorization where needed. If mTLS is a hard requirement, place a verified mTLS-capable gateway in front of the service or choose a host that documents it; prove this in a pre-commit proof of concept. |

## Release gates

1. **Architecture gate:** enforce ADR 0013; pin Node major, Vercel plan, region, separate production/staging project topology, Convex topology, `maxDuration`, and payload budgets.
2. **Transport gate:** from a public stable HTTPS hostname, MCP Inspector and ChatGPT Developer Mode both initialize `/mcp`, discover exactly the three approved tools, validate malformed input, stream/complete a normal call, and demonstrate bounded timeout/disconnect behavior. OpenAI’s required endpoint checks are public HTTPS, Streamable HTTP, tool metadata, and authentication discovery where applicable. [OpenAI: connect and test](https://developers.openai.com/plugins/deploy/connect-chatgpt)
3. **Component gate:** every tool remains model-usable without UI; the message-scoped Evidence component renders only approved hydration, works under its CSP, and a changed bundle/resource URI cannot serve stale incompatible code.
4. **Isolation gate:** Preview/staging/prod variable inventories are compared; preview proves fixture-only behavior; source inspection confirms no credential, corpus, question, answer, token, or raw-provider content is emitted to response, client bundle, platform log, or drain.
5. **Resilience/security gate:** load test stays inside duration/4.5-MB/request/provider budgets; WAF `/mcp` limits allow expected ChatGPT traffic and reject abuse; firewall rules, provider failure, DB failure, and region outage behavior yield safe errors or valid Evidence gaps.
6. **Production gate:** `npm run check`, deterministic evidence gate, staging Developer Mode fidelity suite, production provenance comparison, custom-domain certificate check, sanitized-log review, and a controlled deployment/rollback/restore drill all pass. Re-run the OpenAI evaluation set after any tool schema, metadata, auth, or UI-resource change. [OpenAI: update testing](https://developers.openai.com/plugins/deploy/connect-chatgpt)

## Decision boundary

Vercel is technically feasible for the requested remote MCP plus message-scoped UI asset pattern and is the selected public runtime. Its serverless/Fluid execution provides CDN/WAF, previews, managed TLS, and rapid routing rollback while requiring disciplined streaming time budgets, no reliance on process state, strict log hygiene, and no claim of inbound mTLS until independently proved.
